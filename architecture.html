Data Flow

How a filter change on screen becomes new numbers on screen.

  1. User changes a filter. The filter bar in App.vue updates the shared refs in useFilters: period, warehouse, category, order status.
  2. View reacts. The active view calls getCurrentFilters(), which maps the period to a month value (for example 2025-03 or Q1-2025).
  3. API client builds the request. api.js adds only non-all values as query parameters and calls the FastAPI endpoint with axios.
  4. Backend filters in memory. apply_filters and filter_by_month narrow the preloaded lists. Warehouse matches exactly, while category and status match case-insensitively.
  5. Backend validates and responds. Pydantic response_model types shape the JSON. Summary and report endpoints aggregate totals at request time.
  6. Frontend derives the display. Raw responses are kept in refs (allOrders, inventoryItems). Computed properties produce chart series, KPIs, and table rows.

Known Gaps and Constraints

Observed while reading the code.

AreaStatusDetail
Tasks and purchase-order routes Not in backend api.js calls /api/tasks and /api/purchase-orders, but main.py defines no such routes. Only the Pydantic models exist. Those calls will return 404 until the routes are added.
Persistence By design Data lives in memory and resets on restart. No database.
Security Demo only CORS allows all origins, there is no authentication, and the frontend hard-codes http://localhost:8001.
Inventory filtering By design Inventory has no time dimension, so the period filter does not apply to it.
Quarter logic Duplicated Quarter-to-month mapping appears both as QUARTER_MAP and as inline conditions in /api/reports/quarterly. Both are fixed to 2025.
